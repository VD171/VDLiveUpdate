# VDLiveUpdate (VDLU)

**VDLU - это бесшовный (flashless), инкрементальный движок самообновления для модулей KernelSU / APatch / Magisk: установленный модуль обновляет собственные файлы по подписанному каналу (feed), загружая только то, что изменилось, и применяя большую часть без перезагрузки.**

Обычное обновление модуля снова поставляет весь `.zip` целиком, поэтому несколько изменённых строк стоят полной повторной загрузки, а статический манифест обновления может указывать лишь на один `zipUrl` (одна сборка для всех устройств). VDLU идёт другим путём: он вычисляет разницу между фактически установленным деревом и подписанным, адресуемым по содержимому каналом, загружает только дельты и записывает их на месте. Полная установка arm64 остаётся полной arm64, lite-установка остаётся lite, и модуль никогда не перепрошивается.

VDLU предназначен для **встраивания (vendoring)** в модуль, помещается в `<module>/vdlu/`. Это не самостоятельный модуль.

## Цели

- **Бесшовное самообновление.** Обновлять установленный модуль на месте, по сети, без root-менеджера, без повторной прошивки `.zip` и без потери установленной сборки.
- **Инкрементальность по содержимому.** Передавать только те блобы, содержимое которых изменилось. Адресуемый по содержимому канал (`manifest.json` + `blobs/<sha256>`) означает, что неизменные или откатанные файлы никогда не загружаются повторно.
- **Без перезагрузки там, где это безопасно.** Применять обычные файлы вживую, немедленно. Резервировать подготовленную (staged) перезагрузку только для тех немногих файлов, которым она действительно нужна (`.so`, оверлей `/system`, `sepolicy.rule`).
- **Лёгкость на устройстве.** Чистый POSIX `sh`, без `jq`, без `bash`, без `openssl` на устройстве. Проверка опирается на встроенный `ed25519-mini`; единственный загружаемый бинарник - статический `curl`, используемый только для каналов по `https`.
- **Отказоустойчивость и честность.** Каждое поле манифеста рассматривается как враждебный ввод и проверяется до того, как что-либо будет загружено. Ничто никогда не объявляется "готовым", пока это не докажет повторное хеширование, и ничто не перезаписывается без предварительного резервного копирования.

## Особенности

Что отличает VDLU от типичного OTA-клиента:

- **Бесшовность и инкрементальность.** Адресуемая по содержимому схема diff / fetch / apply с дедупликацией: устройство вычисляет дельту относительно подписанного канала и подтягивает только недостающие блобы.
- **Без перезагрузки, где это возможно.** Обычные файлы применяются вживую; только файлы `.so`, оверлеи `/system` и файлы `sepolicy.rule` подготавливаются и заменяются при единственной перезагрузке. См. [[Reboot Handling]].
- **POSIX `sh` на устройстве.** Работает под toybox / busybox / mksh. Без `jq` (JSON разбирает `awk`-"выпрямитель" в стиле `gron`), без `bash`измов, без тяжёлого рантайма.
- **Лёгкая проверка.** Встроенный `ed25519-mini` проверяет подписи. **На устройстве нет `openssl`**; приватный ключ никогда не попадает ни на устройство, ни в CI.
- **Отказоустойчивая безопасность.** `validate_plan()` отклоняет **весь** манифест при любом некорректном поле (абсолютный путь или путь с `..`, `sha256` не из 64 hex-символов, недопустимый mode / class / encoding). Два профиля, `trusted` и `hardened`, причём `hardened` отказоустойчив за счёт инверсии. См. [[Security and Trust Model]].
- **Возобновляемость и атомарность.** Журнал делает каждую транзакцию устойчивой к сбоям; запись использует `rename` / `mv`; перед любой перезаписью делается резервная копия, поэтому неудавшееся применение откатывается, а не повреждает модуль.
