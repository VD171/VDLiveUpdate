# Feed Format

**Канал (feed)** - это то, что VDLU отдаёт по сети и из чего обновляется устройство. Это простой статический каталог, раздаваемый чем угодно (GitHub Pages, цель rsync, путь `file://`):

```
<source>/
  manifest.json          # the signed description of the current release
  blobs/<sha256>         # one blob per distinct file content
  blobs/<sha256>.gz      # (when the blob is stored gzipped)
```

Сам модуль также поставляет один дополнительный файл, `baseline.json`, внутри `.zip` (не отдаётся из канала). Продюсер, который всё это собирает, описан в [[Producer]]; эта страница - контракт на проводе.

---

## manifest.json

Манифест - это полное описание одного релиза: каждый файл в целевом дереве, что удалить, и подпись над всем этим.

```json
{
  "schema": 1,
  "module": "demo",
  "version": 106,
  "version_name": "v106",
  "built": "2026-11-19T12:00:00Z",
  "engine_min": 3,
  "channel": "stable",
  "key_id": "release-2026",
  "files": [
    {
      "path": "webroot/index.html",
      "sha256": "<hex64>",
      "size": 1234,
      "mode": "0644",
      "enc": "raw",
      "class": "live"
    }
  ],
  "delete": ["webroot/old.html"],
  "sig": "<base64>"
}
```

### Поля

| Поле | Значение |
|---|---|
| `schema` | Версия формата самого манифеста (сейчас `1`). |
| `module` | Id модуля. Устройство отклоняет манифест, если он не совпадает с его собственным id модуля, поэтому валидно подписанный канал для другого модуля не может быть подан вместо него. |
| `version` | Целочисленная версия. Движок обновляет только вперёд; канал старше устройства - это безобидное состояние "ahead", а не ошибка. |
| `version_name` | Человекочитаемая строка версии (например, `v106`). |
| `built` | Временная метка сборки в ISO 8601. Учитывает `SOURCE_DATE_EPOCH` для воспроизводимости. |
| `engine_min` | Минимальная версия движка, требуемая для применения этого манифеста. |
| `channel` | Канал релиза (например, `stable`). |
| `key_id` | Какой ключ в связке устройства подписал этот манифест. Выбирает публичный ключ для проверки, и должен быть в списке разрешённых обновления модуля движка (см. [[Security and Trust Model]]); ключ, всего лишь присутствующий в связке, но не в списке разрешённых, отклоняется до того, как его pubkey будет загружен. |
| `files[]` | **Полное** целевое дерево (не diff). Каждая запись: `path`, `sha256`, `size`, `mode`, `enc` (`raw`/`gz`), `class` (`live`/`soft`/`reboot`). |
| `delete[]` | Пути, присутствовавшие в предыдущем релизе, но теперь исчезнувшие, для удаления устройством. |
| `sig` | Подпись ed25519, base64. См. канонизацию ниже. |

`files[]` описывает **всё** дерево, а не дельту. Устройство само вычисляет дельту, сравнивая манифест с тем, что у него уже есть, и выбирает только те блобы, чьего `sha256` у него нет. `sha256` всегда от оригинального (несжатого) содержимого; `enc` лишь говорит, как блоб хранится в `blobs/`. Смысл `class` и то, что устройство делает с каждым значением, описаны в [[Reboot Handling]].

## Канонизация (подписанные байты)

Это единственный важнейший инвариант формата. PC-подписывающий и проверяющий на устройстве работают на совершенно разных рантаймах (openssl на ПК, toybox + крошечный встроенный проверяющий на устройстве, и **вообще никакой JSON-библиотеки** на устройстве). Они всё равно должны вывести ровно одни и те же байты, чтобы подписать и проверить. Поэтому правило - это намеренное **байтовое преобразование**, а не повторная сериализация JSON.

**Шаг 1: фиксированная форма хранения.** `vdlu-pack` записывает `manifest.json` компактно, с отсортированными ключами, в UTF-8, всегда включая `key_id` и `sig` (как пустые строки до подписания):

```
json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
```

**Шаг 2: убрать только `sig`.** Каноническая форма - это тот самый текст с **удалённым только полем `"sig"`**. Поскольку ключи отсортированы, `sig` всегда появляется как `,"sig":"<value>",`, обрамлённый `"schema"` перед ним и `"version"` после него (оба всегда присутствуют), поэтому его удаление оставляет корректный текст. JSON экранирует каждую `"` внутри строкового значения как `\"`, поэтому структурный токен `"sig":"` однозначен даже против имени файла, которое буквально содержит `"sig":"`.

Удаление - это горстка POSIX-раскрытий параметров, идентичных в подписывающем и проверяющем, без `sed` и без `jq`:

```sh
# $1 = the full manifest text
_pre=${_c%%\"sig\":\"*}     # up to  ...,"schema":N,
_rest=${_c#*\"sig\":\"}      # after "sig":"
_tail=${_rest#*\",}          # after <value>",  ->  "version":...
printf '%s%s' "$_pre" "$_tail" | sha256sum | cut -d' ' -f1
```

**Шаг 3: подписать хеш этого.** Подписываемое/проверяемое сообщение - это **sha256 hex** (64 ASCII-символа, без перевода строки) канонической формы. ed25519 подписывает этот hex.

Два следствия вытекают из этого по построению:

- `key_id` - часть канонической формы (убирается только `sig`). `vdlu-sign` устанавливает `key_id` **до** хеширования, поэтому идентичность ключа покрыта подписью.
- Пустой ли плейсхолдер `sig` (`"sig":""`, во время подписания) или заполненный (во время проверки), его удаление даёт идентичные канонические байты. Подписание и проверка согласуются автоматически.

Два POSIX sh-инструмента авторитетны. Эквивалент на Python, `re.sub(r'"sig":"[^"]*",', '', text, count=1)` затем sha256, существует только для перекрёстной сверки с ними.

Рассуждения о доверии вокруг всего этого (почему проверка на устройстве, как `hardened` отказоустойчив) живут в [[Security and Trust Model]].

## baseline.json (затравка установки)

Когда модуль свеже установлен, он уже должен быть "актуальным" для своей собственной поставляемой версии, без ненужного самообновления только что установленной версии. Именно это делает `baseline.json`.

`baseline.json` поставляется **внутри zip модуля** (по пути `vdlu/baseline.json`), а не в канале. На свежей установке движок засевает свою запись "активной версии" из него, поэтому устройство рождается актуальным, без `from:0` и без повторного fetch того, что у него уже есть.

Ключевые свойства:

- Это **безключевая копия подписанного манифеста** для поставляемой версии: тот же вывод `vdlu-pack`, оставленный без подписи (`key_id` и `sig` остаются пустыми).
- Он **не проверяется**. Движок рассматривает его как локальную доверенную затравку, потому что он прибыл внутри прошитого zip, который является границей доверия установки. Только манифест, *загруженный из канала*, проходит проверку подписи.
- Поскольку ему не нужна подпись, **CI может генерировать его безключево**, что и держит ключ подписи полностью вне CI (см. [[Producer]]).
- `vdlu-pack` **исключает `baseline.json` из собственного манифеста**, поэтому манифест никогда не ссылается на baseline (это была бы петля самоссылки: манифест на baseline на манифест).
- Его отсутствие **не фатально**. Без него устройство просто стартует с `from:0` при первом обновлении и выбирает то, что ему нужно. Никогда не сломано, просто менее оптимально.

## Блобы

Каждое отдельное содержимое файла - это один блоб под `blobs/`, именованный по **sha256 оригинального содержимого**:

- `blobs/<sha256>` для сырого блоба.
- `blobs/<sha256>.gz` для gzip-сжатого блоба (gzip сохраняется только когда файл не меньше 4096 байт и сжатие экономит хотя бы 10 процентов).

Блоб хранится один раз, в одном формате. Адресация по содержимому даёт дедупликацию бесплатно: неизменное, общее или откатанное содержимое отображается на уже существующий блоб, поэтому канал растёт только за счёт действительно нового содержимого, а устройство загружает только недостающие хеши. Устройство проверяет `sha256` каждого загруженного блоба относительно манифеста (после распаковки `gz`-блоба) до использования.

## Что исключено из канала и почему

Канал несёт **только собственное содержимое модуля**. Фиксированный набор путей намеренно держится вне его. `vdlu-pack` применяет один предикат исключения как при обходе дерева, так и при вычислении `delete[]`.

| Исключено | Почему |
|---|---|
| `vdlu/keyring/`, `vdlu/verify/` (корень доверия: сырые публичные ключи + бинарник проверяющего) | **Это основная причина безопасности.** Якорь доверия - **только из прошивки**. Если бы связка или проверяющий были доставляемы через канал, манифест мог бы перезаписать то самое, что его проверяет. Удержание их вне провода означает, что манифест никогда не сможет переписать якорь доверия на устройстве. |
| `vdlu/baseline.json` | Это копия подписанного манифеста (затравка установки); его упаковка была бы петлёй самоссылки. |
| `.vd/` инфраструктура прошивки | Леса flash-gate, поставляемые в zip, никогда не применяемые вживую. |
| `update.json`, `update-mmrl.json` | Их size/sha заполняются CI *после* того, как zip собраны, поэтому поставляемая копия отличается от любой копии в канале. Их подача вызвала бы фантомный fetch единственного файла при первом самообновлении каждой установки, и они всё равно рудиментарны на устройстве (менеджер читает удалённый raw update JSON). |
| `META-INF/`, `customize.sh` (установочные леса) | Потребляются менеджером во время **прошивки** и не сохраняются в установленном модуле. Это не содержимое VDLU; их отдача тратит блобы, и, если бы один из них когда-либо менялся между версиями, он был бы записан как установочный файл в живой каталог модуля. |
| Пофайловые спутники `.sha256` | Они принадлежат только прошиваемому zip, устаревают после инкрементального обновления и удвоили бы манифест. |
| Dev/doc файлы (`RELEASE.md`, `CLAUDE.md`, `.gitignore`) | Никогда не поставляются на устройство; их отдача тратит блобы и колышет подписанный манифест при каждой правке документации. |

Рассуждения, стоящие за исключением корня доверия, раскрыты в [[Security and Trust Model]].

## Семантика delete[]

`delete[]` сообщает устройству, какие пути удалить, чтобы файл, выброшенный между релизами, не оставался на устройстве как сирота. Он вычисляется передачей `--prev <previous manifest.json>` в `vdlu-pack`: путь, который был в предыдущем релизе и отсутствует в текущем, становится записью удаления.

Важное правило: **исключённые пути никогда не выдаются как удаления, даже с `--prev`.** Каждый предыдущий путь прогоняется через тот же предикат исключения, что используется при обходе дерева. Если `--prev` указывает на более старый манифест, который всё ещё перечислял ныне исключённые пути (случайный `baseline.json`, `META-INF/*`, запись связки и так далее), эти пути **не** превращаются в записи удаления. Исключённый путь никогда не был содержимым канала, поэтому его не дело VDLU удалять, и устройству никогда не приказывают удалить файл, который не отдавался через канал. Именно это удерживает список исключений от того, чтобы когда-либо обернуться деструктивной инструкцией.
