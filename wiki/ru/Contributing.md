# Contributing

Вклад приветствуется. VDLU - это бесшовный, инкрементальный движок самообновления,
встраиваемый в модули KernelSU / APatch / Magisk. Эта страница - практический рабочий процесс
разработчика; о том, как части сочетаются, сначала прочитайте [[Architecture]], [[Engine]] и
[[Producer]].

## Ничего не компилируется

VDLU - это скрипты (POSIX sh, немного Python на стороне релиза, vanilla JS для
WebUI), поэтому шага сборки нет. Вы проверяете изменение, прогоняя конвейер
от начала до конца и статически проверяя каждую часть.

## Сначала контракт шва

Интерфейсный контракт между компонентами (сигнатуры CLI, имена файлов и
ключи JSON, общие для движка, продюсера и WebUI) - это **закон
схождения**. Относитесь к нему как к неизменному. Если ваше изменение затрагивает шов
продюсер-движок (схему манифеста, схему журнала, ключи конфига, правило
подписи/канонизации), **сначала выровняйте интерфейсный контракт**, затем
измените код с обеих сторон, чтобы он соответствовал. Изменение на одной стороне шва без
другой молча ломает тех, кто внедрил. См. [[Producer]] про правило канонизации,
о котором подписывающий и проверяющий должны согласиться побайтово.

## Тестируйте от начала до конца перед PR

Запустите продюсер и движок вместе на одноразовом дереве, тем же способом, каким это делает
релиз внедряющего:

```sh
# 1. a signing key
producer/vdlu-keygen demo /tmp/k

# 2. pack a module tree into a feed
producer/vdlu-pack /tmp/tree /tmp/feed demo 1 --version-name v1

# 3. sign the manifest in place
producer/vdlu-sign /tmp/feed/manifest.json /tmp/k/demo.pem demo

# 4. verify the manifest the way the device will (RAW 32B keyring)
engine/vdlu-verify /tmp/feed/manifest.json /tmp/keyring

# 5. drive the engine against the feed (source=file:///tmp/feed in the config)
VDLU_DIR=... MODULE_DIR=... MODID=demo sh engine/update.sh check   # then run / boot
```

Затем статически проверьте каждый компонент:

```sh
sh -n engine/*.sh            # POSIX sh syntax, must pass
node --check webui/vdlu.js   # WebUI JS syntax
```

И откройте `webui/demo.html` в браузере: он имитирует мост root-менеджера
(`ksu.exec`), так что вы можете поупражняться с панелью Updates, тостом прогресса, отменой
и баннером перезагрузки без устройства. См. [[WebUI]].

## Домашние правила

- **POSIX sh на устройстве.** Без bash-измов, кроме `local`, и без `jq`. Оно должно
  работать на toybox / busybox.
- **Безопасность не подлежит обсуждению.** Каждое поле манифеста - враждебный ввод;
  `validate_plan()` остаётся отказоустойчивым, а приватный ключ подписи никогда не касается
  CI или устройства. Не ослабляйте проверку, чтобы пройти тест.
- **Строгость при сбое.** Держите транзакцию возобновляемой: ничто не сообщает "done"
  без совпавшего повторного хеширования, ничто не перезаписывается без резервной копии, и
  применения остаются атомарными.
- **Всегда качество релиза.** Держите комментарии краткими; без избыточных комментариев.
- **Одно логическое изменение на PR.** Говорите, что изменилось и почему.

## Заведение issue

Откройте issue с описанием того, что вы сделали, что ожидали и что произошло.
Для бага приложите id модуля, профиль источника (`hardened` или `trusted`),
команду `update.sh`, которую вы запустили, и релевантный `journal.json` (он записывает
фазу, состояние и ошибку). Для фичи скажите, какой компонент она затрагивает (движок,
продюсер или WebUI), чтобы влияние на шов было ясным с самого начала.
