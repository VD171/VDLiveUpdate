# WebUI

VDLU поставляет опциональный встраиваемый виджет WebUI: небольшую панель "Updates" для WebUI root-менеджера KernelSU или APatch. Она даёт пользователю кнопку Check, кнопку Update now, живой тост прогресса с отменой, баннер перезагрузки и панель настроек, причём пользователю ни разу не нужно касаться терминала.

Это **чистый JavaScript**: ни фреймворка, ни шага сборки, ни CDN. Три файла:

| Файл | Что это |
|---|---|
| `vdlu.js` | виджет; предоставляет `window.VDLU` |
| `vdlu.css` | стили для тоста, баннера и панели (тёмная тема, наследует CSS-переменные хоста) |
| `demo.html` | автономная страница, имитирующая мост устройства, так что весь UI работает в обычном браузере |

Виджет полностью опционален. [[Engine]] прекрасно работает сам по себе от триггеров загрузки; WebUI - это лишь дружелюбное лицо поверх него. См. [[Quick Start]] про включение его в модуль.

## Как UI разговаривает с движком: мост `ksu.exec`

Виджет никогда сам не делает ничего привилегированного. Он собирает shell-команду и передаёт её мосту `ksu.exec` root-менеджера, который выполняет её от root и возвращает stdout / stderr / код возврата. Всё, что показывает панель, читается обратно из файлов, которые пишет движок.

Виджет оборачивает этот мост в единственную функцию `exec(cmd)`, возвращающую `Promise`:

- **resolve** со stdout, когда команда завершилась с кодом 0
- **reject** со stderr (или `rc=N`) в противном случае

Каждая команда несёт окружение контракта, собранное виджетом:

```
VDLU_DIR=... MODULE_DIR=... MODID=... sh $MODULE_DIR/vdlu/update.sh <cmd>
```

Несколько конкретных вызовов:

- **Запустить обновление:** `update.sh run` запускается в **фоне** (`(... &)`), чтобы UI никогда не блокировался долгой загрузкой.
- **Читать прогресс:** лёгкий опрос (примерно раз в секунду) командой `cat $VDLU_DIR/journal.json`.
- **Отмена:** `touch $VDLU_DIR/cancel` (движок останавливается в ближайшей безопасной точке).
- **Конфиг:** чтение и запись `$VDLU_DIR/config` (key=value), с сохранением порядка и неизвестных ключей и изменением только тех ключей, которые пользователь поменял.

Если хост передаёт свои собственные хелперы `exec`, `toast` и `confirm` в `init()`, виджет маршрутизируется через собственную сериализованную очередь команд и визуальные элементы хоста, поэтому он выглядит и ведёт себя как остальная часть того WebUI. Если они опущены, виджет откатывается к прямому вызову `ksu.exec` и внедряет собственный мини-тост.

## Тост прогресса (с отменой)

Как только обновление запущено, виджет показывает неблокирующий угловой тост и опрашивает `journal.json`. Тост отражает конечный автомат движка:

```
PLANNED -> FETCHING -> FETCHED -> APPLYING -> APPLIED_LIVE -> (PENDING_REBOOT | DONE)
```

Он отрисовывает полосу прогресса плюс строку `phase done/total - current file - bytes` и несёт кнопку **Cancel** на всём протяжении. Терминальные состояния получают каждое своё оформление:

- **DONE** -> зелёный тост, "vX applied - all verified".
- **PENDING_REBOOT** -> зелёный тост плюс постоянный баннер перезагрузки (ниже).
- **ERROR** -> красный тост с причиной из `journal.error` или stderr, предлагающий Retry. Он никогда не подделывает успех.
- **Cancelled** -> янтарный тост, "cancelled - N/M applied, resumable", предлагающий **Resume**.
- **DEFERRED** -> мягкий синий информационный тост, "download deferred, waiting for the allowed network". Это безобидное ожидание по сетевой политике, а не ошибка; оно возобновляется при следующей проверке или загрузке в нужной сети.

Опрос защищён. Наполовину записанный журнал (движок пишет параллельно) игнорируется на этот такт, вместо того чтобы быть неправильно разобранным. Если журнал исчезает после того, как прогресс уже наблюдался, это означает, что commit очистил его: виджет сообщает DONE. Если журнал отсутствует с самого начала в течение 8 тактов, он сообщает "no response". А если журнал застывает на одних и тех же значениях в течение 20 тактов, виджет проверяет `lock.d` движка: если блокировка жива, это просто медленная загрузка единственного блоба, и тост продолжает ждать; если блокировка мертва, запуск умер на полпути, поэтому виджет выводит ошибку с кнопкой Resume вместо того, чтобы вечно крутить "updating".

## Баннер перезагрузки

Некоторые файлы нельзя заменить на живой системе: `.so`, оверлей `/system`, `sepolicy.rule`. Движок подготавливает их и помечает транзакцию `PENDING_REBOOT`. Виджет тогда показывает **постоянный верхний баннер**: "Reboot to activate the new `.so` (vX)". Он остаётся, пока подготовленные файлы не будут заменены при следующей загрузке. При открытии WebUI баннер переоценивается из журнала, поэтому пользователь, закрывший и снова открывший UI, всё равно его видит. См. [[Reboot Handling]] про то, что происходит при загрузке.

Заметьте, что баннер привязан к терминальному состоянию `PENDING_REBOOT`, а не к флагу `reboot_pending` (который становится истинным, как только любой `.so` попадает в план). Это удерживает баннер от появления посреди запуска, до того как что-либо фактически подготовлено.

## Панель "Updates": независимые переключатели по категориям

`mountUpdatesPanel(el)` отрисовывает панель настроек в пустой `<div>`, предоставленный хостом. У неё три секции, и каждый элемент управления независим и сохраняется сам по себе:

**Actions**
- **Check for updates** -> запускает `check`, показывает результат встроенно (актуально / новее канала / доступно обновление с количеством файлов и тегом reboot).
- **Update now** -> запускает `run` плюс тост прогресса.

**Automation** (независимые переключатели, каждый пишется в `config` в момент переключения)
- **On WebUI open** (`auto_on_webui_open`) -> запускать тихое обновление при открытии UI.
- **On reboot** (`auto_on_reboot`) -> применять в pre-zygote при загрузке.
- **Boot retry every (s)** и **Boot retry up to (min)** -> числовые поля для повтора загрузки манифеста, когда устройство загружается офлайн.

**Source**
- `source` (URL канала), `channel` (stable / canary), `profile` (trusted / hardened) и селектор **Network**, отображаемый на `net_policy` (Wi-Fi + mobile / Wi-Fi only / mobile only).

Переключатели и числовые поля сохраняются немедленно и визуально откатываются, если запись не удалась. Текстовые поля и селекторы в секции Source помечают себя как изменённые (dirty) и сохраняются вместе по явной кнопке Save. Панель всегда переписывает только те ключи, которых коснулся пользователь, поэтому любые неизвестные или будущие ключи конфига сохраняются.

### Поведение авто-открытия

`onWebUIOpen()` вызывается при загрузке хоста. Он оценивает журнал (показывая баннер перезагрузки или предлагая Resume для нетерминальной транзакции, оставленной предыдущей сессией), затем, если `auto_on_webui_open=1`, сначала запускает **тихий** `check()`. Постоянный тост прогресса и фактический `run` срабатывают только когда есть реальная загрузка (`update && fetch > 0`). Если устройство актуально или опережает канал, результат показывается встроенно в панели и ни один тост не остаётся на экране, поэтому авто-обновление так же ненавязчиво, как ручная кнопка.

## i18n (строки по языкам)

Каждая строка UI по умолчанию на **английском**, что является нейтральным выбором для публичных многоязычных модулей. Полная карта ключей живёт в объекте `DEFAULT_I18N` в `vdlu.js` (также доступна как `VDLU.i18n`). Хост переопределяет любое подмножество ключей, передавая карту в `init({ i18n: ... })`:

```html
<script src="i18n/pt-BR.js"></script>   <!-- defines window.VDLU_I18N_PT_BR -->
<script>
  VDLU.init({ exec: ex, moduleDir: MOD, vdluDir: VDL, modid: 'x',
              i18n: window.VDLU_I18N_PT_BR });
</script>
```

- **Частичная** карта допустима: любой отсутствующий ключ откатывается к английскому значению по умолчанию.
- Метки фаз и состояний используют ключи `ph_<phase>` и `st_<STATE>`; остальные - плоские ключи вроде `cancel`, `updateNow`.
- Проработанный перевод (`i18n/pt-BR.js`) поставляется как шаблон; новый язык - это просто файл `i18n/<lang>.js` той же формы, либо хост строит карту из своей собственной системы i18n.

## demo.html: запустить UI без устройства

`demo.html` имитирует мост `ksu.exec`, так что ровно те же `vdlu.js` и `vdlu.css` работают в обычном браузере, без root и без телефона:

```sh
xdg-open webui/demo.html
```

Мок симулирует `update.sh` и эволюционирующий `journal.json`, а его кнопки переключают между сценариями: живое обновление вплоть до DONE, завершение с `reboot_pending`, ошибка на полпути и отменяемый запуск. Это самый быстрый способ увидеть UI и итеративно его дорабатывать, и именно это вы проверяете до встраивания виджета в модуль.

## Включение в модуль (триггер открытия WebUI)

Хостовый `index.html` загружает два файла и вызывает три функции:

```html
<link rel="stylesheet" href="vdlu.css">
<script src="vdlu.js"></script>
<script>
  VDLU.init({
    moduleDir: '/data/adb/modules/' + MODID,   // $MODULE_DIR (where the engine is vendored)
    vdluDir:   '/data/adb/' + MODID + '/vdlu',  // $VDLU_DIR  (Tier-2 state, outside the module dir)
    modid:     MODID,
    module:    'Demo',        // friendly name shown in the toast (default: modid)
    exec:   ex,               // optional: the host's ksu.exec wrapper
    toast:  toast,            // optional: the host's transient toast
    confirm: askConfirm       // optional: the host's modal
  });

  VDLU.onWebUIOpen();                          // the WebUI-open trigger: banner + auto-update eval
  VDLU.mountUpdatesPanel('b-updates');         // render the "Updates" tab into an empty div
</script>
```

Хосту нужно лишь предоставить пути Tier-2 и выделить один пустой `<div>` для панели; тост и баннер виджет внедряет в `document.body` сам. `onWebUIOpen()` - это триггер открытия WebUI: именно он оценивает баннер перезагрузки, предлагает Resume на прерванной транзакции и запускает тихое авто-обновление, когда установлено `auto_on_webui_open`.

### Единственный источник, встраиваемый повторно байт в байт

`vdlu.js` и `vdlu.css` - это **каноническая копия**. Модуль, встраивающий виджет, повторно встраивает эти файлы без изменений в свой `webroot/`; он никогда не редактирует свою копию на месте. Новая фича рождается в канонических файлах и спускается вниз через повторное встраивание. Редактирование встроенной копии порождает тихий дрейф (это случалось: устаревшая копия лишилась `net_policy`, тоста DEFERRED и полей повтора при загрузке). Страж паритета в дереве исходников находит каждую копию и помечает или повторно встраивает те, что разошлись, покрывая только виджет; у связки ключей (keyring) свой ритм "проверить, а не копировать".

### Публичный API (`window.VDLU`)

| Функция | Что делает |
|---|---|
| `init(opts)` | настроить виджет; возвращает `window.VDLU` |
| `onWebUIOpen()` | вызвать при загрузке: баннер, предложение Resume и тихое авто-обновление |
| `mountUpdatesPanel(el)` | отрисовать панель Updates в `el` (строка-id или элемент) |
| `check()` | запустить `update.sh check`; `Promise<{update, from, to, fetch, reboot}>` |
| `startUpdate()` | запустить `run` в фоне плюс тост прогресса с Cancel |
| `cancel()` | создать `$VDLU_DIR/cancel` (движок останавливается в безопасной точке) |
| `resume()` | возобновить текущую транзакцию плюс тост |
| `refreshBanner()` | переоценить постоянный баннер ожидающей перезагрузки |
