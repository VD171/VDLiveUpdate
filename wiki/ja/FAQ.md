# FAQ

よく出てくる質問への短い回答です。それぞれ、完全な話があるページにリンクしています。

## 「フラッシュ不要」とはどういう意味ですか? 最初はやはりフラッシュしますか?

はい、一度だけフラッシュします。モジュールは通常のやり方で(root マネージャーで zip を
フラッシュして)インストールされます。「フラッシュ不要」とは、その後のすべての更新を説明します。
VDLU は変わったファイルだけを取得してその場で適用するので、数行の変更を配布するためだけに
フルの zip を再フラッシュすることは決してありません。[[Architecture]] を参照してください。

## 更新には再起動が必要ですか?

たいていは不要です。ほとんどのファイル(あなたの WebUI、バイナリ、ライブラリ、各種設定、
`module.prop`)は **live** クラスで、再起動なしにアトミックに適用されます。再起動クラスのファイル
(`zygisk/` の下の `.so`、`/system/**` オーバーレイ、`*.rule` sepolicy ファイル)だけが
**ステージング**され、次回のブート時に入れ替えられます。動作中のプロセスがすでにライブの inode を
マップしているからです。それが起こると、WebUI は永続的な「reboot to activate」バナーを表示します。
[[Reboot Handling]] を参照してください。

## フィードが MITM されたり毒を盛られたりしても安全ですか?

はい、`hardened` フィードでは安全です。すべてのマニフェストフィールドは敵対的な入力として
扱われます。マニフェストはその正準形に対する有効な ed25519 署名を運ばなければならず、
`validate_plan()` が**いかなるダウンロードより前に**フェイルクローズドで実行されます。絶対または
`..` パス、64 桁の 16 進でない `sha256`、無効な mode、class、encoding があれば、マニフェスト全体を
拒否します。マニフェストはあなたのモジュール id にも束縛されるので、別のモジュール用に正当に
署名されたフィードをすり替えて提供することはできません。すべての blob の sha256 は、プロファイルに
関わらずダウンロード後に検証されます。[[Security and Trust Model]] を参照してください。

## 端末上で何が必要ですか(依存関係)?

ごくわずかです。純粋な POSIX sh(mksh / busybox / toybox)に加えて、toybox の `sha256sum`、
`gzip`、`base64`、`date`、組み込みの `ed25519-mini` 検証器、そして `https` ソースの場合にのみ、
一度取得されて Tier-2 にキャッシュされる静的な `curl`。`file://` ソースには curl はまったく
不要です。**`jq` への依存はありません**。エンジンは JSON を `awk` で書かれた gron スタイルの
フラット化処理で解析します。[[Engine]] を参照してください。

## 端末上で openssl は必要ですか?

いいえ。`openssl` は PC/リリース側(`vdlu-keygen`、`vdlu-sign`)でのみ使われます。端末上では、
署名の検証は生の 32 バイト公開鍵を読む軽量な組み込み `ed25519-mini` バイナリを使います。
[[Producer]] と [[Security and Trust Model]] を参照してください。

## 署名鍵をどうローテーションしますか?

`vdlu-keygen` で新しい鍵ペアを生成し、新しい生の 32 バイト公開鍵を以前のものと並べて端末
キーリングに追加し、新しい `key_id` で署名を始めます。端末はマニフェストの `key_id` によって
`<keyring>/<key_id>.pub` を選ぶので、エンジンの変更は不要です。現在と以前の両方の公開鍵を
配布することで、ローテーションされた鍵が古いインストールをブリックすることは決してありません。
[[Security and Trust Model]] を参照してください。

## hardened と trusted - どちらを使いますか?

あらゆる公開フィード(`https` 越し、例えば GitHub Pages で提供)には `hardened` を使ってください。
署名を必須にし、ダウングレードをブロックします。`trusted` は、あなたがすでに管理している
プライベートな `file://` または SSH ステージングソースにのみ使ってください。そこでは署名は
ベストエフォートです(すべての blob のハッシュは依然としてチェックされます)。迷ったら `hardened` を
使ってください。それがフェイルクローズドなデフォルトであり、`trusted` でないあらゆる値は
`hardened` として扱われます。[[Security and Trust Model]] を参照してください。

## blob が改ざんされたり、マニフェストが不正だったりしたら?

更新は中止され、何も適用されません。不正なマニフェストは、いかなる fetch より前に
`validate_plan()` によって丸ごと拒否されます。sha256 がマニフェストと一致しない blob は拒否されます。
同一 blob での 3 回の失敗で、何も適用せずに fetch フェーズを中止します。致命的な失敗があれば、
ジャーナルは `ERROR` を記録し、モジュールはそのまま残されます。[[Engine]] を参照してください。

## 更新が私のファイルを削除したり端末をブリックしたりできますか?

リスクは設計によって封じ込められています。上書きおよび削除されるファイルは、まず
`rollback/<version>/` へバックアップされ、`apply` は成功したバックアップなしに上書きする代わりに
中止します。削除はトランザクションが `DONE` に到達したときにのみ実行され、再起動が保留中の間は
決して実行されません。失敗した適用は、すでに書き込んだライブファイルを復元します。パスは使用前に
モジュールディレクトリ内の封じ込めについて検証されるので、マニフェストがツリーの外に書き込んだり
削除したりすることはできません。[[Engine]] と [[Security and Trust Model]] を参照してください。

## KernelSU と Magisk と APatch で動きますか?

はい。VDLU はモジュールにベンダリングされるプレーンな POSIX sh に WebUI を加えたものなので、
KernelSU、APatch、Magisk で同様に動作します。root マネージャーの WebUI ブリッジ(`ksu.exec`)を
使ってエンジンを駆動し、進捗をポーリングします。[[Architecture]] と [[WebUI]] を参照してください。

## 端末上のフットプリントはどれくらい大きいですか?

小さいです。エンジンはスクリプトで、唯一のバイナリは ABI ごとの `ed25519-mini` 検証器(とても
小さい)と、`https` ソースの場合は一度取得されてキャッシュされる静的な `curl`(約 1MB)です。
すでに自身の `curl` をバンドルしているモジュールはそれを再利用し、ダウンロードはまったく
追加されません。Tier-2 の blob キャッシュは検証済みの内容に加えて直近 3 つのロールバック
バージョンを保持します。[[Engine]] と [[Architecture]] を参照してください。
