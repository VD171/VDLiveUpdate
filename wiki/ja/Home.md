# VDLiveUpdate (VDLU)

**VDLU は、KernelSU / APatch / Magisk モジュール向けのフラッシュ不要かつ増分的な自己更新エンジンです。インストール済みのモジュールが、署名付きフィードを通じて自身のファイルを更新し、変更があった部分だけを取得して、そのほとんどを再起動なしで適用します。**

通常のモジュール更新は `.zip` 全体を再び配布するため、数行の変更でもフルの再ダウンロードが必要になり、静的な更新マニフェストは単一の `zipUrl`(すべての端末に対して一つのフレーバー)しか指し示せません。VDLU は別のやり方をとります。実際にインストールされているツリーを、署名付きのコンテンツアドレス方式のフィードと差分比較し、差分だけをダウンロードして、その場で書き込みます。arm64 のフルインストールは arm64 フルのまま、lite インストールは lite のままとなり、モジュールが再フラッシュされることは決してありません。

VDLU は、モジュールに **ベンダリング**(組み込み)して `<module>/vdlu/` に配置することを意図しています。それ自体が独立したモジュールではありません。

## 目的

- **フラッシュ不要の自己更新。** インストール済みのモジュールをその場で、オーバーザエア(OTA)で更新します。root マネージャーも、`.zip` の再フラッシュも不要で、インストール済みのフレーバーも失われません。
- **コンテンツによる増分化。** 内容が変わった blob だけを転送します。コンテンツアドレス方式のフィード(`manifest.json` + `blobs/<sha256>`)により、変更のないファイルや元に戻されたファイルが再取得されることはありません。
- **安全な範囲で再起動不要。** 通常のファイルはライブで即座に適用します。真に再起動を必要とするわずかなファイル(`.so`、`/system` オーバーレイ、`sepolicy.rule`)についてのみ、ステージングされた再起動を確保します。
- **端末上で軽量。** 純粋な POSIX `sh` のみ。端末上に `jq`、`bash`、`openssl` はありません。検証は組み込みの `ed25519-mini` に乗ります。取得されるバイナリは、`https` フィード用にのみ使われる静的な `curl` だけです。
- **フェイルクローズドで誠実。** マニフェストのすべてのフィールドは敵対的な入力として扱われ、何かをダウンロードする前に検証されます。再ハッシュで証明されない限り「完了」と報告されることは決してなく、まずバックアップを取らずに何かが上書きされることもありません。

## 特徴

VDLU が一般的な OTA クライアントと異なる点:

- **フラッシュ不要で増分的。** 重複排除を伴うコンテンツアドレス方式の差分 / 取得 / 適用。端末は署名付きフィードに対する差分を計算し、不足している blob だけを取得します。
- **可能な限り再起動不要。** 通常のファイルはライブで適用され、`.so`、`/system` オーバーレイ、`sepolicy.rule` ファイルだけがステージングされ、一度の再起動で入れ替えられます。[[Reboot Handling]] を参照してください。
- **端末上では POSIX `sh`。** toybox / busybox / mksh の下で動作します。`jq` は不要で(`gron` スタイルの `awk` フラット化処理が JSON を解析します)、`bash` 固有の構文も、重いランタイムもありません。
- **軽量な検証。** 組み込みの `ed25519-mini` が署名を検証します。**端末上に `openssl` はありません。** 秘密鍵が端末や CI に触れることは決してありません。
- **フェイルクローズドなセキュリティ。** `validate_plan()` は、いずれかの不正なフィールド(絶対パスや `..` パス、64 桁の 16 進数でない `sha256`、無効な mode / class / encoding)があれば、マニフェスト**全体**を拒否します。`trusted` と `hardened` の二つのプロファイルがあり、`hardened` は反転によってフェイルクローズドです。[[Security and Trust Model]] を参照してください。
- **再開可能でアトミック。** ジャーナルによってすべてのトランザクションがクラッシュセーフになります。書き込みには `rename` / `mv` を使い、上書きの前にはバックアップを取るため、適用の失敗はモジュールを破損させる代わりにロールバックします。
