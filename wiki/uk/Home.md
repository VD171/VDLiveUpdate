# VDLiveUpdate (VDLU)

**VDLU - це інкрементний рушій самооновлення без перепрошивки для модулів KernelSU / APatch / Magisk: встановлений модуль оновлює власні файли через підписаний стрічковий канал (feed), завантажуючи лише те, що змінилося, і застосовуючи більшість змін без перезавантаження.**

Звичайне оновлення модуля знову відвантажує весь `.zip`, тож кілька змінених рядків коштують повного повторного завантаження, а статичний маніфест оновлення може вказувати лише на один `zipUrl` (один варіант для всіх пристроїв). VDLU обирає інший шлях: він порівнює (diff) дерево, яке фактично встановлене, з підписаним feed, адресованим за вмістом, завантажує лише дельти та записує їх на місці. Повне встановлення arm64 лишається arm64 full, lite-встановлення лишається lite, і модуль ніколи не перепрошивається.

VDLU призначений для **вбудовування (vendoring)** в модуль, у теку `<module>/vdlu/`. Він не є окремим модулем.

## Цілі

- **Самооновлення без перепрошивки.** Оновлювати встановлений модуль на місці, через мережу, без root-менеджера, без повторної прошивки `.zip` і без втрати встановленого варіанта.
- **Інкрементність за вмістом.** Передавати лише ті blob-и, вміст яких змінився. Адресований за вмістом feed (`manifest.json` + `blobs/<sha256>`) означає, що незмінені чи відкочені файли ніколи не завантажуються повторно.
- **Без перезавантаження там, де це безпечно.** Застосовувати звичайні файли наживо, одразу. Залишати поетапне (staged) перезавантаження лише для тих небагатьох файлів, які справді цього потребують (`.so`, overlay `/system`, `sepolicy.rule`).
- **Компактність на пристрої.** Чистий POSIX `sh`, без `jq`, без `bash`, без `openssl` на пристрої. Перевірка тримається на вбудованому `ed25519-mini`; єдиний завантажуваний бінарник - статичний `curl`, що використовується лише для `https`-feed-ів.
- **Fail-closed і чесність.** Кожне поле маніфесту трактується як ворожий вхід і перевіряється перед тим, як щось завантажиться. Ніщо не позначається як "виконано", доки повторне хешування цього не доведе, і ніщо не перезаписується без попереднього резервування.

## Особливості

Що відрізняє VDLU від типового OTA-клієнта:

- **Без перепрошивки та інкрементно.** Diff / fetch / apply, адресовані за вмістом, із дедуплікацією: пристрій обчислює дельту відносно підписаного feed і тягне лише відсутні blob-и.
- **Без перезавантаження, де можливо.** Звичайні файли застосовуються наживо; лише `.so`, overlay `/system` та `sepolicy.rule` ставляться у staged і підмінюються за одне перезавантаження. Див. [[Reboot Handling]].
- **POSIX `sh` на пристрої.** Працює під toybox / busybox / mksh. Без `jq` (JSON розбирає розплющувач у стилі `gron`, написаний на `awk`), без конструкцій `bash`, без важкого runtime.
- **Компактна перевірка.** Вбудований `ed25519-mini` перевіряє підписи. **На пристрої немає `openssl`**; приватний ключ ніколи не торкається ні пристрою, ні CI.
- **Безпека fail-closed.** `validate_plan()` відхиляє **увесь** маніфест за будь-яким хибним полем (абсолютний шлях або `..`, `sha256`, що не є 64 hex-символами, некоректний mode / class / encoding). Є два профілі, `trusted` та `hardened`, причому `hardened` є fail-closed за інверсією. Див. [[Security and Trust Model]].
- **З можливістю відновлення та атомарність.** Журнал робить кожну транзакцію стійкою до збоїв; записи використовують `rename` / `mv`; резервна копія створюється перед будь-яким перезаписом, тож невдале застосування відкочується, а не псує модуль.
