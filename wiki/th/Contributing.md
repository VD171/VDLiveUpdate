# การร่วมสนับสนุน

ยินดีรับการร่วมสนับสนุน VDLU เป็นเอนจินอัปเดตตัวเองแบบเพิ่มทีละส่วนไม่ต้องแฟลช
ที่ฝังเข้าไปในโมดูล KernelSU / APatch / Magisk หน้านี้คือเวิร์กโฟลว์ dev
เชิงปฏิบัติ; สำหรับการที่ชิ้นส่วนต่าง ๆ ประกอบเข้ากัน อ่าน [[Architecture]], [[Engine]] และ
[[Producer]] ก่อน

## ไม่มีอะไรต้องคอมไพล์

VDLU เป็นสคริปต์ (POSIX sh, Python เล็กน้อยฝั่งรีลีส, vanilla JS สำหรับ
WebUI) ดังนั้นจึงไม่มีขั้นตอนบิลด์ คุณตรวจสอบการเปลี่ยนแปลงโดยการรันไปป์ไลน์
ตั้งแต่ต้นจนจบและโดยการตรวจสอบแบบสแตติกแต่ละชิ้น

## สัญญารอยต่อก่อน

สัญญาอินเทอร์เฟซระหว่างคอมโพเนนต์ (ลายเซ็น CLI, ชื่อไฟล์ และคีย์
JSON ที่แบ่งใช้โดยเอนจิน producer และ WebUI) คือ **กฎแห่งการ
ลู่เข้า (law of convergence)** จงถือว่ามันไม่เปลี่ยนรูป หากการเปลี่ยนแปลงของคุณแตะต้อง
รอยต่อ producer-ไป-เอนจิน (สคีมา manifest, สคีมา journal, คีย์คอนฟิก,
กฎลายเซ็น/การทำ canonical) **ให้ปรับสัญญาอินเทอร์เฟซก่อน** แล้วจึงเปลี่ยน
โค้ดทั้งสองฝั่งให้ตรงกัน การเปลี่ยนแปลงฝั่งหนึ่งของรอยต่อโดยไม่มี
อีกฝั่งทำลายผู้นำเข้าใช้อย่างเงียบ ๆ ดู [[Producer]] สำหรับกฎการทำ canonical
ที่ตัวลงลายเซ็นและตัวตรวจสอบต้องเห็นพ้องต้องกันแบบไบต์ต่อไบต์

## ทดสอบตั้งแต่ต้นจนจบก่อน PR

รัน producer และเอนจินด้วยกันบนต้นไม้ไฟล์ทิ้งขว้าง ด้วยวิธีเดียวกับที่รีลีส
ของผู้นำเข้าใช้ทำ:

```sh
# 1. a signing key
producer/vdlu-keygen demo /tmp/k

# 2. pack a module tree into a feed
producer/vdlu-pack /tmp/tree /tmp/feed demo 1 --version-name v1

# 3. sign the manifest in place
producer/vdlu-sign /tmp/feed/manifest.json /tmp/k/demo.pem demo

# 4. verify the manifest the way the device will (RAW 32B keyring)
engine/vdlu-verify /tmp/feed/manifest.json /tmp/keyring

# 5. drive the engine against the feed (source=file:///tmp/feed in the config)
VDLU_DIR=... MODULE_DIR=... MODID=demo sh engine/update.sh check   # then run / boot
```

แล้วตรวจสอบแบบสแตติกแต่ละคอมโพเนนต์:

```sh
sh -n engine/*.sh            # POSIX sh syntax, must pass
node --check webui/vdlu.js   # WebUI JS syntax
```

และเปิด `webui/demo.html` ในเบราว์เซอร์: มันจำลองสะพานโปรแกรมจัดการ root
(`ksu.exec`) เพื่อให้คุณสามารถใช้งานแผง Updates, toast ความคืบหน้า, การยกเลิก
และแบนเนอร์รีบูตโดยไม่มีอุปกรณ์ ดู [[WebUI]]

## กฎของบ้าน

- **POSIX sh บนอุปกรณ์** ไม่มี bashism เกินกว่า `local` และไม่มี `jq` มันต้อง
  ทำงานบน toybox / busybox
- **ความปลอดภัยต่อรองไม่ได้** ทุกฟิลด์ใน manifest เป็นอินพุตที่เป็นปฏิปักษ์;
  `validate_plan()` คงเป็น fail-closed และคีย์ลงลายเซ็นส่วนตัวไม่เคยแตะต้อง
  CI หรืออุปกรณ์ อย่าผ่อนคลายการตรวจสอบเพื่อให้ test ผ่าน
- **เข้มงวดเมื่อล้มเหลว** คงให้ธุรกรรมดำเนินต่อได้: ไม่มีสิ่งใดรายงาน "done"
  โดยไม่มีการแฮชซ้ำที่ตรงกัน ไม่มีสิ่งใดถูกเขียนทับโดยไม่มีการสำรอง และ
  การ apply คงเป็นอะตอมมิก
- **คุณภาพระดับรีลีสเสมอ** คงให้คอมเมนต์กระชับ; ไม่มีคอมเมนต์ที่เกินจำเป็น
- **หนึ่งการเปลี่ยนแปลงเชิงตรรกะต่อหนึ่ง PR** บอกว่าอะไรเปลี่ยนไปและทำไม

## การแจ้งปัญหา

เปิด issue อธิบายสิ่งที่คุณทำ สิ่งที่คุณคาดหวัง และสิ่งที่เกิดขึ้น
สำหรับบั๊ก ให้ใส่ id โมดูล โปรไฟล์ต้นทาง (`hardened` หรือ `trusted`)
คำสั่ง `update.sh` ที่คุณรัน และ `journal.json` ที่เกี่ยวข้อง (มันบันทึก
เฟส สถานะ และข้อผิดพลาด) สำหรับฟีเจอร์ ให้บอกว่ามันแตะต้องคอมโพเนนต์ใด (engine,
producer หรือ WebUI) เพื่อให้ผลกระทบต่อรอยต่อชัดเจนตั้งแต่ต้น
