# คำถามที่พบบ่อย

คำตอบสั้น ๆ สำหรับคำถามที่เกิดขึ้นบ่อยที่สุด แต่ละข้อลิงก์ไปยังหน้าที่มี
เรื่องราวฉบับเต็ม

## "ไม่ต้องแฟลช" หมายความว่าอย่างไร ครั้งแรกยังต้องแฟลชไหม

ใช่ คุณแฟลชหนึ่งครั้ง โมดูลถูกติดตั้งด้วยวิธีปกติ (แฟลช zip ใน
โปรแกรมจัดการ root ของคุณ) "ไม่ต้องแฟลช" อธิบายทุกการอัปเดตหลังจากนั้น: VDLU fetch
เฉพาะไฟล์ที่เปลี่ยนไปและนำไปใช้ ณ ตำแหน่งเดิม ดังนั้นคุณจึงไม่เคยแฟลช zip
เต็มก้อนซ้ำเพียงเพื่อส่งโค้ดที่เปลี่ยนไปไม่กี่บรรทัด ดู [[Architecture]]

## การอัปเดตต้องรีบูตไหม

โดยปกติไม่ ไฟล์ส่วนใหญ่ (WebUI, ไบนารี, ไลบรารี, คอนฟิก, `module.prop` ของคุณ)
เป็นคลาส **live** และนำไปใช้แบบอะตอมมิกโดยไม่ต้องรีบูต มีเพียงไฟล์คลาสรีบูต
(`.so` ภายใต้ `zygisk/`, overlay `/system/**`, ไฟล์ sepolicy `*.rule`) เท่านั้นที่ถูก
**จัดเตรียม** และสลับเข้าในการบูตครั้งถัดไป เพราะโปรเซสที่ทำงานอยู่ได้แมป
inode ที่ใช้งานอยู่ไว้แล้ว เมื่อเกิดเช่นนั้น WebUI จะแสดงแบนเนอร์ "reboot to
activate" แบบคงอยู่ ดู [[Reboot Handling]]

## ปลอดภัยไหมหากฟีดถูก MITM หรือถูกวางยา

ใช่ บนฟีด `hardened` ทุกฟิลด์ใน manifest ถูกปฏิบัติเสมือนเป็นอินพุตที่เป็นปฏิปักษ์
manifest ต้องพกลายเซ็น ed25519 ที่ถูกต้องครอบคลุมรูปแบบ canonical ของมัน และ
`validate_plan()` รันแบบ fail-closed **ก่อนการดาวน์โหลดใด ๆ**: มันปฏิเสธ manifest
ทั้งก้อนเมื่อเจอเส้นทางแบบสมบูรณ์หรือ `..`, `sha256` ที่ไม่ใช่ hex 64 ตัว
หรือ mode คลาส หรือ encoding ที่ไม่ถูกต้อง manifest ยังถูกผูกกับ id โมดูลของคุณ
ดังนั้นฟีดที่ลงลายเซ็นถูกต้องสำหรับโมดูลอื่นจึงไม่สามารถถูกเสิร์ฟแทนที่ได้
`sha256` ของทุก blob ถูกตรวจสอบหลังการดาวน์โหลดไม่ว่าจะโปรไฟล์ใด ดู
[[Security and Trust Model]]

## มันต้องการอะไรบนอุปกรณ์ (dependencies)

น้อยมาก POSIX sh ล้วน ๆ (mksh / busybox / toybox) บวกกับ `sha256sum`,
`gzip`, `base64` และ `date` ของ toybox; ตัวตรวจสอบ `ed25519-mini` ที่ฝังมา; และเฉพาะสำหรับ
ต้นทาง `https` ก็มี `curl` แบบสแตติกที่ fetch ครั้งเดียวและแคชไว้ใน Tier-2
ต้นทาง `file://` ไม่ต้องใช้ curl เลย **ไม่มี dependency กับ `jq`**: เอนจิน
แจง JSON ด้วยตัวทำให้แบนสไตล์ gron ที่เขียนด้วย `awk` ดู [[Engine]]

## ต้องใช้ openssl บนอุปกรณ์ไหม

ไม่ `openssl` ถูกใช้เฉพาะฝั่ง PC/รีลีส (`vdlu-keygen`, `vdlu-sign`)
บนอุปกรณ์ การตรวจสอบลายเซ็นใช้ไบนารี `ed25519-mini` ที่ฝังมาและเพรียวบาง
ซึ่งอ่านคีย์สาธารณะดิบ 32 ไบต์ ดู [[Producer]] และ
[[Security and Trust Model]]

## ฉันจะหมุนคีย์ลงลายเซ็นอย่างไร

สร้างคู่คีย์ใหม่ด้วย `vdlu-keygen` เพิ่มคีย์สาธารณะดิบ 32 ไบต์ใหม่เข้าไปใน
keyring ของอุปกรณ์ข้าง ๆ อันก่อนหน้า และเริ่มลงลายเซ็นด้วย `key_id` ใหม่
อุปกรณ์เลือก `<keyring>/<key_id>.pub` ตาม `key_id` ของ manifest
ดังนั้นจึงไม่ต้องเปลี่ยนเอนจิน การส่งทั้งคีย์สาธารณะปัจจุบันและก่อนหน้า
หมายความว่าคีย์ที่หมุนแล้วไม่เคยทำให้การติดตั้งเก่ากลายเป็นอิฐ ดู [[Security and Trust Model]]

## hardened กับ trusted - ฉันควรใช้อันไหน

ใช้ `hardened` สำหรับฟีดสาธารณะใด ๆ (เสิร์ฟผ่าน `https` เช่น GitHub Pages)
มันทำให้ลายเซ็นเป็นข้อบังคับและบล็อกการลดเวอร์ชัน ใช้ `trusted` เฉพาะสำหรับ
ต้นทาง `file://` ส่วนตัวหรือ SSH ที่คุณควบคุมอยู่แล้ว ซึ่งลายเซ็น
เป็นแบบพยายามอย่างดีที่สุด (แฮชของทุก blob ก็ยังถูกตรวจสอบ) เมื่อสงสัย ใช้ `hardened`:
มันเป็นค่าเริ่มต้นแบบ fail-closed และค่าใด ๆ ที่ไม่ใช่ `trusted` จะถูกปฏิบัติเป็น
`hardened` ดู [[Security and Trust Model]]

## จะเกิดอะไรขึ้นหาก blob ถูกดัดแปลงหรือ manifest ผิดรูปแบบ

การอัปเดตจะยกเลิกและไม่มีสิ่งใดถูกนำไปใช้ manifest ที่ผิดรูปแบบถูกปฏิเสธทั้งก้อน
โดย `validate_plan()` ก่อนการ fetch ใด ๆ blob ที่ sha256 ไม่ตรงกับ
manifest จะถูกปฏิเสธ; ความล้มเหลวสามครั้งบน blob เดียวกันยกเลิกเฟส fetch โดย
ไม่นำสิ่งใดไปใช้ เมื่อเกิดความล้มเหลวหนักใด ๆ journal จะบันทึก `ERROR` และโมดูล
ถูกปล่อยไว้คงเดิม ดู [[Engine]]

## การอัปเดตสามารถลบไฟล์ของฉันหรือทำให้อุปกรณ์กลายเป็นอิฐได้ไหม

ความเสี่ยงถูกบรรจุไว้โดยการออกแบบ ไฟล์ที่ถูกเขียนทับและลบถูกสำรองก่อน
ไปที่ `rollback/<version>/` และ `apply` ยกเลิกแทนที่จะเขียนทับโดยไม่มีการ
สำรองที่สำเร็จ การลบรันเฉพาะเมื่อธุรกรรมไปถึง `DONE` ไม่เคย
ขณะที่ยังมีรีบูตค้างอยู่ การ apply ที่ล้มเหลวจะคืนค่าไฟล์ live ที่มันเขียนไปแล้ว
เส้นทางถูกตรวจสอบการบรรจุภายในไดเรกทอรีโมดูลก่อนใช้งาน
ดังนั้น manifest จึงไม่สามารถเขียนหรือลบนอกต้นไม้ไฟล์ได้ ดู [[Engine]] และ
[[Security and Trust Model]]

## มันทำงานบน KernelSU และ Magisk และ APatch ไหม

ใช่ VDLU เป็น POSIX sh ล้วน ๆ บวกกับ WebUI ฝังเข้าไปในโมดูล ดังนั้นมันจึงทำงานบน
KernelSU, APatch และ Magisk เหมือนกัน มันใช้สะพาน WebUI ของโปรแกรมจัดการ root
(`ksu.exec`) เพื่อขับเคลื่อนเอนจินและ poll ความคืบหน้า ดู [[Architecture]] และ
[[WebUI]]

## footprint บนอุปกรณ์ใหญ่แค่ไหน

เล็ก เอนจินเป็นสคริปต์; ไบนารีเดียวคือตัวตรวจสอบ `ed25519-mini` ต่อ ABI
(จิ๋ว) และสำหรับต้นทาง `https` ก็มี `curl` แบบสแตติก (~1MB) ที่
fetch ครั้งเดียวและแคชไว้ โมดูลที่แพ็ก `curl` ของตัวเองมาอยู่แล้วจะใช้มันซ้ำ
และไม่เพิ่มการดาวน์โหลดเลย แคช blob ใน Tier-2 เก็บเนื้อหาที่ตรวจสอบแล้วบวกกับ
เวอร์ชัน rollback 3 เวอร์ชันล่าสุด ดู [[Engine]] และ [[Architecture]]
