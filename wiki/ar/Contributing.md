# Contributing

المساهمات مرحّب بها. VDLU محرّك تحديث ذاتي تزايدي بلا فلاش،
مُضمَّن في وحدات KernelSU / APatch / Magisk. هذه الصفحة هي سير العمل التطويري
العملي؛ ولمعرفة كيف تتلاءم القطع، اقرأ [[Architecture]] و[[Engine]] و
[[Producer]] أولًا.

## لا شيء يُترجَم (compile)

VDLU سكربتات (POSIX sh، وقليل من بايثون على جانب الإصدار، وvanilla JS لـ
WebUI)، فلا توجد خطوة بناء. تتحقّق من تغيير بتشغيل خطّ الأنابيب
من طرف إلى طرف وبالفحص الثابت لكل قطعة.

## عقد الوصلة أولًا

عقد الواجهة بين المكوّنات (تواقيع CLI، وأسماء الملفات، و
مفاتيح JSON المشتركة بين المحرّك والمنتِج وWebUI) هو **قانون
التقارب**. عامله كثابت لا يتغيّر. إن مسّ تغييرك وصلة
المنتِج-المحرّك (مخطّط البيان، مخطّط السجلّ، مفاتيح الإعداد،
قاعدة التوقيع/التقنين)، **حاذِ عقد الواجهة أولًا**، ثم
غيّر الشفرة على الجانبين لتتطابق. تغيير على جانب من الوصلة دون
الآخر يكسر المتبنّين بصمت. انظر [[Producer]] لقاعدة التقنين
التي يجب أن يتّفق عليها الموقّع والمُتحقِّق بايتًا ببايت.

## اختبر من طرف إلى طرف قبل PR

شغّل المنتِج والمحرّك معًا على شجرة مؤقّتة، بالطريقة نفسها التي يفعلها
إصدار متبنٍّ:

```sh
# 1. a signing key
producer/vdlu-keygen demo /tmp/k

# 2. pack a module tree into a feed
producer/vdlu-pack /tmp/tree /tmp/feed demo 1 --version-name v1

# 3. sign the manifest in place
producer/vdlu-sign /tmp/feed/manifest.json /tmp/k/demo.pem demo

# 4. verify the manifest the way the device will (RAW 32B keyring)
engine/vdlu-verify /tmp/feed/manifest.json /tmp/keyring

# 5. drive the engine against the feed (source=file:///tmp/feed in the config)
VDLU_DIR=... MODULE_DIR=... MODID=demo sh engine/update.sh check   # then run / boot
```

ثم افحص كل مكوّن ثابتًا:

```sh
sh -n engine/*.sh            # POSIX sh syntax, must pass
node --check webui/vdlu.js   # WebUI JS syntax
```

وافتح `webui/demo.html` في متصفّح: فهو يحاكي جسر مدير الروت
(`ksu.exec`)، فتستطيع تجريب لوحة Updates، وتوست التقدّم، والإلغاء،
ولافتة إعادة التشغيل بلا جهاز. انظر [[WebUI]].

## قواعد البيت

- **POSIX sh على الجهاز.** لا تعبيرات bash تتجاوز `local`، ولا `jq`. يجب أن
  يعمل على toybox / busybox.
- **الأمان غير قابل للتفاوض.** كل حقل بيان مدخل عدائي؛
  يبقى `validate_plan()` فاشلًا مغلقًا، ومفتاح التوقيع الخاص لا يلمس
  CI ولا جهازًا أبدًا. لا تُرخِ فحصًا لتمرير اختبار.
- **صرامة عند الإخفاق.** أبقِ المعاملة قابلة للاستئناف: لا شيء يبلّغ "done"
  دون إعادة تجزئة متطابقة، ولا شيء يُكتب فوقه دون نسخة احتياطية، و
  التطبيقات تبقى ذرّية.
- **جودة إصدار دائمًا.** أبقِ التعليقات موجزة؛ بلا تعليقات زائدة.
- **تغيير منطقي واحد لكل PR.** قل ما تغيّر ولماذا.

## رفع المشكلات (issues)

افتح مشكلة تصف ما فعلت، وما توقّعت، وما حدث.
للعلّة (bug)، أدرج معرّف الوحدة، وملف المصدر الشخصي (`hardened` أو `trusted`)،
وأمر `update.sh` الذي شغّلته، وملف `journal.json` ذا الصلة (يسجّل
المرحلة والحالة والخطأ). للميزة، قل أي مكوّن تمسّ (المحرّك،
المنتِج، أو WebUI) كي يكون أثر الوصلة واضحًا مقدّمًا.
