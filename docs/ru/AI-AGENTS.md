# Управление VDLU из ИИ-агента

VDLiveUpdate (VDLU) представляет собой бесфлешовый инкрементальный апдейтер, который модули KSU/Magisk встраивают в `vdlu/`. Весь движок управляется из шелла, так что ИИ-ассистент или агент может проверить, применить, возобновить и завершить обновление безголово, тот же цикл, что гоняет WebUI, без UI и без человека в контуре. Разбирайте JSON, который он печатает, никогда не скрапьте текст.

## Контракт

Одна точка входа, запускаемая как root на устройстве, с тремя заданными переменными окружения движка:

```sh
VDLU_DIR=/data/adb/<mod>/vdlu MODULE_DIR=/data/adb/modules/<mod> MODID=<mod> \
  sh "$MODULE_DIR/vdlu/update.sh" <verb>
```

- `VDLU_DIR` обозначает каталог состояния Tier-2 (вне модуля, переживает перепрошивку), `MODULE_DIR` обозначает живое дерево модуля, `MODID` обозначает id модуля.
- `rc 0` = ок, `rc != 0` = ошибка, с причиной на stderr.
- Читающие глаголы (`check`, `status`) печатают **один объект JSON** в stdout. Разбирайте его, никогда не скрапьте текст.
- Движок зависит только от toybox (`sha256sum`/`gzip`/`base64`) плюс встроенного `ed25519-mini` плюс статического `curl`, загружаемого при первом https-обновлении, ноль `jq`.

Во время разработки тот же скрипт лежит в `engine/update.sh` в этом репозитории, так что `sh engine/update.sh <verb>` с тремя заданными переменными управляет тестовой копией тем же образом.

## Глаголы

| Глагол | Делает | Печатает |
|------|------|--------|
| `check` | DIFF только для чтения против фида, ничего не меняет | `{"update":bool,"from":N,"to":M,"fetch":K,"reboot":bool}`, или `{"update":false,"ahead":true,"from":N,"to":M}`, когда устройство впереди фида (понижение заблокировано, безобидно, rc 0) |
| `run` | полный LIVE-цикл DIFF -> FETCH -> APPLY -> COMMIT, применяет файлы LIVE и стейджит REBOOT-hard, уважает `cancel` | прогресс в `journal.json` |
| `resume` | возобновляет отложенную транзакцию с её текущей фазы, идемпотентно, никогда не подменяет `.so` | обновлённый `journal.json` |
| `boot` | режим pre-zygote, `resume` плюс подмена застейдженного `.so`, закрывает `PENDING_REBOOT` в `DONE` | обновлённый `journal.json` |
| `status` | снимок только для чтения, ничего не меняет | `journal.json`, или `{"state":"idle"}`, когда никакая транзакция не активна |
| `cancel` | запрашивает остановку, идущий `run` останавливается в следующей безопасной точке | создаёт `$VDLU_DIR/cancel` |

Безголовое обновление выглядит так: `check`, чтобы увидеть, есть ли что-то в ожидании, `run`, чтобы применить всё, что может пойти в живую, затем `boot` при следующей загрузке, чтобы подменить любой застейдженный `.so` (или `resume`, чтобы повторить отложенную загрузку). Каждый глагол безопасно вызывать снова, сбой или обрыв сети посреди цикла оставляет возобновляемый журнал, никогда не полуприменённый модуль.

## JSON статуса

`status` (и живой файл в `$VDLU_DIR/journal.json`) представляет собой контракт прогресса, который читают и WebUI, и агент:

```json
{ "schema":1, "module":"<id>", "target":<version>, "from":<version>,
  "phase":"diff|fetch|apply|commit",
  "state":"PLANNED|FETCHING|FETCHED|APPLYING|APPLIED_LIVE|PENDING_REBOOT|DONE|ERROR|DEFERRED",
  "total":<int>, "done":<int>, "current":"<path>", "bytes":<int>,
  "reboot_pending":bool, "cancelled":bool, "error":"<str|null>",
  "updated":"<ISO8601>",
  "items":[ {"path":"<p>","sha256":"<h>","class":"<c>","st":"pending|fetched|applied|staged|skipped"} ] }
```

- `state` движется в фиксированном порядке: `PLANNED -> FETCHING -> FETCHED -> APPLYING -> APPLIED_LIVE -> (PENDING_REBOOT | DONE)`.
- `DONE` достигается только после того, как повторный хэш всего совпал. Застейдженный файл REBOOT-hard даёт `PENDING_REBOOT`, никогда ложный `DONE`, запустите `boot`, чтобы завершить его.
- `DEFERRED` означает, что `net_policy` заблокировала загрузку, безобидное и возобновляемое состояние, а не ошибка, план сохраняется и следующий `check`/`boot` продолжает.
- `ERROR` несёт причину в `error`, применённые файлы LIVE откатываются из `rollback/`, модуль никогда не остаётся полуприменённым.
- `cancelled:true` с `error:null` означает чистую остановку, журнал остаётся возобновляемым.

## Контракт шва

Каждый компонент (движок, продюсер, WebUI) соответствует [`INTERFACES.md`](INTERFACES.md), закону сходимости. Глаголы CLI, схема `manifest.json`, ключи `journal.json` и заданные там ключи config **неизменны**, относитесь к этому файлу как к единственному источнику истины и выравнивайтесь по нему, прежде чем менять любой из них. По внутренностям движка (возобновляемая транзакция, гарантии строгости, исключение trust-anchor) см. [`ENGINE.md`](ENGINE.md), по стороне фида (сборка и подпись адресуемого по содержимому фида) см. [`PRODUCER.md`](PRODUCER.md).

## Правила для агента

- Используйте глаголы и JSON, никогда не скрапьте WebUI и никогда не редактируйте файлы состояния вручную.
- Относитесь к `INTERFACES.md` как к неизменному, изменение означает сначала выровнять контракт.
- Патч от ИИ-агента проходит ту же планку ревью, что и любой другой, build всегда release, ничего не ослабляйте, ничего не теряйте.
